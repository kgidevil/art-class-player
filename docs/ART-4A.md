# ART 4A — release candidate v1.0.0-rc.1
## Backup and restore
- Single .saibackup binary file (SAIBKP01 prefix, length, SHA-256 manifest digest, UTF-8 JSON manifest, original blobs concatenated). This is not ZIP. Original bytes unchanged, no network upload. Sequential SHA-256 per photo; 512MiB total, 50MiB/image, 5000 photos, 8MiB header. Browser memory/quota may impose lower limits, especially iPad. Export may fail for larger libraries; never delete originals to work around it without separate backups.
- Includes original local and provided images, stable IDs/credits, settings, class profiles/programs/history, favorites, cached catalog, auto-download setting and paused session. Temporary drawing/analysis effects, PWA caches, browser permissions excluded. Backup contains personal data, unencrypted: keep private. No merge, explicit whole-library replacement only.
- Validate schema, allowed keys, metadata, IDs, image sizes, manifest/photo digest, references, decode on target device before any mutation. Hashes detect accidental damage, not a signature or authenticity proof. IndexedDB v2 preserves photo store; replacement transaction includes pending settings journal. If transaction fails, existing photos remain. On reboot journal is replayed before React mounts; if localStorage quota/access fails app blocks with retry, new photo data and journal remain. Not a cross-storage atomic commit; recover by resolving quota/access. Use one tab and make a separate target backup first. No background sync of private data.
- Windows test transfers backup to fresh browser context, rejects corrupted bytes, checks settings/class/preset and exact restored photo bytes. This does not prove iPad transfer. Export file link needs explicit user tap/save.
## Performance and final UX
Memoized filtered lists, candidate ranking, downloaded map, image view and stable handlers; saved photo gallery initially renders 60 items with more button; pointer redraw coalesced per animation frame; safe-area padding. Full original image blobs remain in IndexedDB; object URLs remain resident for active library; no guarantee of memory ceiling. 3-hour simulated deadline test, not wall-clock or device endurance. No unverified iPad claim.
## Release gates
Build/unit/content/security/Windows browser tests, actual GitHub Pages deployment and HTTPS URL, manual Windows backup/restore, iPad install/restore/offline/Pencil, HDMI mirroring and actual 3-hour class test. Release candidate until all gates pass. Pages owner must choose Settings > Pages > Source > GitHub Actions if not enabled; rerun CI workflow. No release tag until user confirms hardware gates.
